对象为同目录 `process_choice.wl`、`process_choice.nb` 与中文教程。本例公式为原创教学设定，没有使用外部数据或私人研究材料。软件手册仅作为函数行为参考，未复制手册内容或附带软件文件。

## 已完成的数学与独立计算检查

原始成本差为 $C_A-C_B=2q-12$、$C_A-C_C=5q/2-f$、$C_B-C_C=12+q/2-f$。据此推导区域不等式和有效边界段；三个有限实数总有最小值，按 A、B、C 顺序取首个最小值可唯一分类。教程所列条件正是该选择规则的简化形式。

使用 Python 3.14.6 标准库 `fractions.Fraction` 独立计算。对每个点分别计算原始三项成本，取成本最小者中排序最前者，再与简化区域条件比较。所有计算使用有理数，不以浮点容差处理并列。

网格为 $q=0,1/4,\ldots,12$、$f=0,1/2,\ldots,24$，共 2401 点：

| B 固定费用 | A 点数 | B 点数 | C 点数 | 最小成本并列点 | 两种判定不一致点 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 12（基准） | 841 | 372 | 1188 | 31 | 0 |
| 16（练习） | 945 | 104 | 1352 | 21 | 0 |

另核验三重交点、交点上下左右相距 $1/100$ 的点、原点和 $(12,0)$。交点分别为 $(6,15)$ 与 $(8,20)$，均归 A；$(7,24)$ 的选择从 B 变为 A。默认坐标轴和各有效边界段的精确归属已按成本差核算。

有限网格只证明这些采样点上的实现一致性。连续区域结论依据上面的代数比较，不由网格外推。

## Mathematica 实际运行

运行环境为 Mathematica 13.3.1 for Microsoft Windows (64-bit)。通过本地 WolframScript 的 `-local` 指定内核，以 `-file` 执行检查脚本，并使用内外两层时间限制。启动探针、完整计算、图像导出、notebook 检查分开执行；前面三个阶段均正常退出。

基准文件用 `Get` 执行；练习只在内存中将 B 固定费用由 12 改为 16，仓库源码保留基准值。两组均获得：

- `GridPoints -> 2401`、`GridMismatches -> 0`，各工艺点数与上表的独立 Python 核算一致。
- `SymbolicRegionChecks -> {True, True, True}`：三次 `Reduce` 均找不到区域条件与原始成本判定不同的点。
- `SampleChecksPassed -> True`、`TriplePointChoice -> "A"`，三重交点分别为 `{6,15}` 与 `{8,20}`。
- 三个 `RegionPlot` 与合并图形均为 `Graphics`，`GraphicsConstructed -> True`。

Notebook 先通过 Wolfram 解析，再通过 `UsingFrontEnd` 与 `NotebookOpen[..., Visible -> False]` 隐藏打开，用 `NotebookEvaluate[..., InsertResults -> False]` 执行三个输入单元。基准验证摘要和全部 15 行代表点结果正确返回，随后关闭了 notebook。此步骤验证了相对路径载入和实际求值；没有模拟手动点击或 Shift+Enter，也没有检查可见窗口交互。

Notebook 检查在结果全部返回后，辅助进程退出超过 60 秒预算；本次辅助进程被按其进程关系结束，后续检查无残留。已完成的求值结果保留，但不将此阶段描述为正常退出，也未为收尾问题重跑已成功计算。
