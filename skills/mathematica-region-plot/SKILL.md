# Mathematica 二维区域图

交付能从已提供的定义重新计算的区域图；图的填色、边界线和文字说明应对应同一个判定规则。

## 从模型到判定条件

先确定公式来源、横纵轴、参数值、绘图范围、各方案可行条件、比较目标和并列规则。缺失且影响结果的条件应明确提出，不能用绘图惯例替代模型假设。已有 notebook 的保存输出不能替代生成它的输入定义。

对每个位置先筛选可行方案，再比较目标值。最大利润和最小成本使用相反的比较方向；若方案内部还含优化问题，应先确定候选解和取值域，再进行方案之间的比较。无可行方案的区域单独标明，不随意分给某一方案。

将并列规则落实为互斥条件。例如三个全域可行方案按 A、B、C 的顺序打破最小成本并列，可写成：

```wolfram
regionA = costA <= costB && costA <= costC;
regionB = costB < costA && costB <= costC;
regionC = costC < costA && costC < costB;
```

以上写法要求成本是有限实数且三个方案均可行。若引入数值容差，说明容差的量纲与用途；不要用容差悄悄改变精确并列的数学定义。

## 组织可复现代码

- 将参数、成本或收益、可行条件、区域判定、检查、绘图依次组织。计算变量使用普通符号，排版标签可以另行设置。
- 检查函数的默认参数、辅助定义、初始化单元、外部文件和被赋值的绘图变量。只清理本次使用的符号，避免清空其他计算。
- 简单解析条件直接交给 `RegionPlot`。数值函数需要在数值采样点返回可判定结果；把求解、文件读取等耗时操作移到采样函数之外。
- 交付 `.wl` 源码；需要 notebook 时提供 `.nb`，并说明它是独立文件还是依赖同目录源码。使用相对路径，列明实际依赖。
- 修改已有文件前核对源文件和当前内容；保留所需输入单元、嵌入对象与用户已有修改。保存过的输出可能过时，应指出要重新运行哪些输入。

## 先核验，再绘图

1. 从目标值相等式推导候选边界，并检查其上其他方案的目标值。两方案相等不意味着它们在该处最优。
2. 检查可行域边缘、坐标轴、交点、并列点和边界两侧。用原始成本或收益直接比较，核对绘图判定；避免仅重复调用同一个分类器作为验证。
3. 对简单模型用代数化简或符号求解核实边界和区域覆盖。适量网格用于发现实现错误，有限网格不能证明连续域上的全部性质。
4. 分别构建各区域，再用 `Show` 合并。先采用适中的采样密度；薄区域或曲率较大的边界需要定向增加采样并复核。
5. 只强调真正改变最终选择的边界段。边界上的精确归属由判定式与说明表达；图像像素和线宽无法表达严格不等式。

图形应有变量名称、范围和能辨认的方案标签或图例。配色、字体、尺寸和导出格式依实际用途选择，不作为模型条件。

## 执行、排错与交付

区分静态检查、内核实际执行、图形对象构建、图像导出和视觉检查。解析成功不等于执行成功；生成 `Graphics` 也不证明导出正常。

运行前设定与任务规模相称的时间预算。空图先检查代表点、数值参数与可行条件；出现未求值表达式先查依赖；慢图先缩小计算问题，再考虑增加资源。导出受阻时保留有效源文件和已完成检查，说明具体阻塞，避免无依据地反复重试。

交付说明至少包含使用入口、软件及外部依赖、公式或数据来源、已执行检查及其结果、尚未验证部分。是否需要图像、矢量文件或可编辑后处理文件，由任务决定。
